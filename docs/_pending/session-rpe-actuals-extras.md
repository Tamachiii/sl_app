Replace, in the same bullet, the sentence that starts "The client **normalizes a value equal to its target back to `null`**" (up to "for the un-overridden dimension).") with:

On a set of the exercise as the coach wrote it, the client **normalizes a value equal to its target back to `null`**, so a populated `actual_*` there denotes a genuine deviation — what `formatActual(log)` renders, falling back to the target for the un-overridden dimension. Two kinds of set store **both values as entered**, because their targets are not what was done: a set of a **swapped** exercise (`slot_deviations.kind = 'swap'` with a substitute — the pinned `target_*` are the ORIGINAL exercise's, and `lib/doneSetHistory` nulls them, so the substitute's records and "Last time" read the logged actuals and nothing else; an empty load is stored as `0`, because `null` would read as the original exercise's load in `formatActual` and Stats) and an **extra set** (`is_student_added`, no targets). On those two `hasLoggedActual(log)` means "values were logged", not "off plan": the coach's Off-plan band in [SessionReview.jsx](../src/components/coach/SessionReview.jsx) lists them. `SetRow` gets the swap from [SlotGroupCard.jsx](../src/components/student/SlotGroupCard.jsx) as `swapped`, computed with the test of `lib/doneSetHistory` (`kind === 'swap'` and a `substitute_exercise_id`), so what the row stores and what the history reads cannot disagree.

Replace, in the bullet that starts "**A set_log has three outcome states: pending, done, failed.**", the sentence "The gesture that marks a set done — the tap or the swipe — opens the RPE selector, so the student can rate without an extra tap; marking a set failed opens nothing, because RPE is locked there." with:

Add after the bullet that starts "**A set_log has three outcome states: pending, done, failed.**":

- **An RPE or an Actual given on a PENDING set marks it done, in the same write.** The athlete who rates a set, or writes down what it was, has done it: written alone, the rating left the set pending, and a session rated set by set was confirmed with no set done — no volume, no record, no "Last time", every set "not done" for the coach. On a pending set (neither done nor failed) [SetRow.jsx](../src/components/student/SetRow.jsx) sends `{ logId, rpe, done: true }` to `useSetRpe` and `{ logId, actualReps, actualWeightKg, done: true }` to `useLogActual`; `patchForRpe` / `patchForActual` in [`lib/offlineMutations.js`](../src/lib/offlineMutations.js) then build ONE patch with the value and `patchForDone(true, at)`, for the optimistic row and for the request alike, and a refused write takes back the rating and the tick together. Never on a done set (it would date the set again and can move `performed_on`), never on a failed one (`patchForDone` would turn it into a done set), never for a rating taken back (`null`) or an Actual cleared: there the payload is the value alone, as it was, which is also what a write queued by an older build carries. Only `done === true` is the marker. No new mutation key: the set-log writes are still five, one row each. Tests: `src/components/student/SetRow.test.jsx`, `SetRow.replay.test.jsx` (one queued write, which lands done, rated and dated), `src/hooks/useSetLogs.tapTime.test.jsx`, `src/hooks/useSetLogs.optimistic.test.jsx`, `src/lib/offlineMutations.test.js`.
- **An extra set is done only once it says what was done.** It is inserted with no targets and nothing else (`useAddStudentSet`): values written at the insert would make an untouched extra set a logged set, which locks the coach's editor and refuses the exercise's removal. Every gesture of `SetRow` that would mark an extra set done while it has no reps (above 0) and no load (`0` = bodyweight, no load added) — the tap, the swipe, an RPE — opens its Actual editor instead, and Save stays disabled, with `sessionRpeActualsExtras.extraNeedsRepsAndLoad` under it, until the inputs hold both; on a pending set that Save writes them and marks the set done (previous bullet). On an exercise prescribed in seconds an extra set has no reps to give — `set_logs` has no column for an actual duration — so only the load is asked for (`extraNeedsLoad`); `SlotGroupCard` passes the unit as `durationBased`, read like the slot summary reads it (the first set with a target, else the slot's own columns). A done extra set keeps its values: Clear is not offered there. A done extra set without values written by an older build stays done.
- **The Actual editor of a swapped exercise and of an extra set opens on seeds, worked out by `editorSeeds` in [SlotGroupCard.jsx](../src/components/student/SlotGroupCard.jsx).** A swapped exercise: the substitute's last performance (`lastPerformance[substitute_exercise_id]`), set by set in set order, the last of its sets for any set beyond them; without one, the set before it in this session as it was done, and the prescribed reps for the first (the same scheme, as Stats reads it) — never the original exercise's load. An extra set: the set before it as it was done — its actual values, else its targets, and `0` kg after a set prescribed at bodyweight; an extra set after an extra set carries them on. A skipped set passes nothing on. What the set already holds always comes first. The sets of the exercise as the coach wrote it open on their own targets. Tests: `src/components/student/SlotGroupCard.test.jsx` (the card and the real rows).
