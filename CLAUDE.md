# CLAUDE.md — Working Notes for Future Agents

Per-turn context only. Heavier docs load on demand.

## When to load the other docs

- **`docs/INVARIANTS.md`** — touching: routing/scroll-shell, the theme, RLS, `set_logs` schema, rest timer (in-app or Web Push), the Edge Functions, messaging/notifications triggers and realtime, offline mutations and what the device stores, auth and sign-out, service worker and app updates, the deploy, coach session review, stats persistence, role-aware `UserMenu`, the session QUEUE / training dates / day strips. **Load before any DB or hook change.** Skip for pure UI polish, copy, or component-local edits.
- **`docs/ARCHITECTURE.md`** — adding a DB table, changing RLS, touching React Query keys, changes spanning 3+ modules, or orienting to the data model / periodization / routing persistence. Skip for single-component edits, UI polish, tests, copy changes.
- **`docs/DESIGN_SYSTEM.md`** — where Parc lives in the code (the copies of its tokens and classes, `parc-app.css`, `components/parc`) and the UI rules the app holds itself to. The rules of the design system are in `design/parc/`. Skip for logic, data wiring, routing.
- **`design/parc/`**: the Parc design system (light theme). Read `design/parc/README.md` before any UI change, take every value from `design/parc/tokens.json`, and follow the matching mock in `design/parc/screens/`.
- **`README.md`** — setup, deployment, high-level overview, onboarding. Skip for day-to-day coding.
- **`docs/RUNBOOK.md`** (+ `docs/runbook/`) — what the owner does by hand in production, and when: the checkpoints, which migrations each one applies, the Auth dashboard steps, and — `docs/runbook/70-admin-procedures.md` — what the owner does outside a checkpoint: the monthly run of `run_retention()`, and where the statement for each other case is written. Load when writing a migration's runbook page or changing anything the user must do by hand. Its commands target production: an agent writes and tests them, and runs them only in a session the user opens for a checkpoint ("Who runs a checkpoint" in the index) — never as part of a package.
- **`supabase/migrations/README.md`** — the format of a migration (file, audit, rollback, runbook page, manifest entry). Load before any DB change.
- **`docs/BACKLOG.md`** — what the 2026-09 review left for the redesign project: the translation and accessibility of every screen, the product features of waves 5 to 8, the contract migrations 43–45 and the compatibility code they would remove, the SQL performance and tooling packages of wave 4, each with its finding ids. Load when planning one of them. Skip for anything else.

## Read-sparingly rule

For any feature, walk the dependency graph — don't scan folders:

1. Page/component the feature changes.
2. Its direct imports only (hooks, components, helpers). Not siblings.
3. `src/routes.jsx` only if adding a route or wrapper.
4. `supabase/schema.sql` or a migration only if touching the DB.
5. Tests for files in steps 1–2 only.

Prefer `Grep` over `Read` for locating symbols. Read ranges (`offset`/`limit`) for files > 200 lines. Don't re-Read a file already in context.
